# PR 4: Profile, Targets, Rich Menu and Today Overview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 填完個人檔案後，按 Rich Menu「今日總覽」會顯示自己的每日目標（spec §10 PR 4 完成條件）。

**Architecture:**

- 目標計算（Mifflin-St Jeor × 活動係數 ± 目標調整、安全下限、營養素分配）是純函式，放在 `packages/shared`。LIFF 用它即時預覽，`api` 用它計算後存檔，兩邊的數字保證一致。
- `api` 新增 `user_profiles`、`body_metrics` 兩張表，以及個人檔案 API（LIFF session）與 `/internal/users/today`（bot）。
- `bot` 處理 Rich Menu 的 postback，回覆今日總覽 Flex。
- Rich Menu 圖片由 HTML 在 CI 用 headless Chrome 產生，再由手動觸發的 workflow 上傳到 LINE 並設為預設選單，所有機密都在 CI 內處理。

**Tech Stack:** 沿用 PR 3（Fastify、drizzle、pglite、FastAPI、line-bot-sdk v3、React、@line/liff、Terraform、GitHub Actions），沒有新增執行期套件。

**Spec:** [docs/specs/2026-10-15-gym-assistant-coach-design.md](../../specs/2026-10-15-gym-assistant-coach-design.md) §5（`user_profiles`、`body_metrics`）、§6.1、§6.2、§6.7、§10 PR 4、§10.1 核准設計稿（Rich Menu、Flex 今日總覽、LIFF 首次設定、個人檔案、我的紀錄、設定）。

## Global Constraints

- 沿用 PR 3 的所有 Global Constraints：`api` 是唯一的資料庫存取者；bot→api 用 Google ID token；LIFF→api 用 1 小時 session；webhook 在請求內回覆；機密只放 Secret Manager；錯誤回應只用 `ApiError`，5xx 不外洩細節；繁體中文；按鈕高度 ≥ 44px；畫面依方向 C 設計 token。
- 「哪一天」一律以 **Asia/Taipei** 日期計算（§5）。
- 年齡限制：18 歲以上（§12 #1）。出生年必須讓今年年齡落在 18–100。
- **安全下限**：建議熱量不低於 BMR，且女性不低於 1,200 kcal、男性不低於 1,500 kcal。手動覆寫低於下限時顯示警告，但仍允許儲存（§6.2）。
- 目標計算的常數（下列為本計畫的決定，spec 只寫「± 目標調整」）：
  - 活動係數：`sedentary` 1.2、`light` 1.375、`moderate` 1.55、`active` 1.725、`very_active` 1.9
  - 目標調整：`cut` −500 kcal、`maintain` 0、`bulk` +250 kcal
  - 蛋白質（g／kg 體重）：`cut` 2.0、`maintain` 1.6、`bulk` 1.8
  - 脂肪：熱量的 25%（÷ 9）
  - 碳水：剩餘熱量 ÷ 4，最低 0
  - 熱量四捨五入到 10 kcal，克數四捨五入到整數
- Rich Menu：2500×1686，3 欄 × 2 列，依核准設計稿；`chatBarText` 為「選單」。
- Flex 只用 token 的顏色與圓角（LINE 用系統字型）。

## Review Focus

1. **計算結果低於下限**：例如矮小、低活動量的女性選減脂，計算值要被拉到下限，並標記 `clampedToFloor`。由 Task 1 測試涵蓋。
2. **今年剛滿 18 歲或未滿**：出生年 2008 在 2026 年算 18 歲，可以；2009 要被拒絕。由 Task 1、Task 3 測試涵蓋。
3. **沒有個人檔案就按「今日總覽」**：bot 回覆「先完成個人檔案」與 LIFF 連結，不能出錯或回空卡片。由 Task 3、Task 5 測試涵蓋。
4. **重複送出個人檔案**：同一天再填一次體重要覆蓋同一筆 `body_metrics`（每人每天一筆），不能新增第二筆。由 Task 2 測試涵蓋。
5. **台北日期換日**：UTC 16:00 之後已是台北的隔天，`today` 與 `body_metrics.measured_on` 必須用台北日期。由 Task 1、Task 2 測試涵蓋。

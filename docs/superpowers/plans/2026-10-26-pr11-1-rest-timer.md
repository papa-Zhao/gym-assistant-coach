# PR 11.1: 休息計時改善 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 休息計時一直固定在畫面頂端；休息結束時 Android 震動、iOS 播提示音、畫面閃爍；訓練中螢幕保持亮著；每組的休息時間顯示在組列表，也能在新的訓練紀錄頁看到。

**Architecture:** 全部在 LIFF，只有訓練紀錄頁需要一個新的唯讀 API（`GET /workouts/history`），不用改資料庫。`restSec` 已經在新增組數時寫入 `workout_sets.rest_sec`（[ActiveWorkout.tsx:418](../../../apps/liff/src/pages/workout/ActiveWorkout.tsx)），這次只是把它顯示出來。提醒相關的瀏覽器 API（震動、Web Audio、Wake Lock）包在 `restAlert.ts`、`wakeLock.ts` 兩個小模組，方便測試時替換。

**Tech Stack:** 現有套件（React、Vitest、Testing Library、Fastify、Drizzle）。不加新依賴。

**Spec:** 2026-10-26 手機測試回饋第 5、6、7 項（本計畫「已決定」一節是需求來源）；規格 [docs/specs/2026-10-15-gym-assistant-coach-design.md](../../specs/2026-10-15-gym-assistant-coach-design.md) 的訓練紀錄章節。

**PR 11 系列順序：** 11.1 休息計時（本份）→ 11.2 動作辨識與滑輪把手 → 11.3 自訂動作照片圖示（含政策改版）→ 11.4 訓練完的建議。每份都要等前一份合併後才開始實作，因為 `ActiveWorkout.tsx`、`workouts/repo.ts` 會一直被改到。

## 已決定（2026-10-26，使用者同意）

1. 休息結束提醒採 A+B+C：Android 震動加長成連震三下；iOS 播提示音並讓畫面閃爍；訓練中用 Screen Wake Lock 讓螢幕保持亮著。LINE 推播提醒（D）這次不做。
2. 每組休息：組列表加一欄「休息」，紀錄頁也要顯示每組休息。
3. 休息計時改成固定在畫面頂端（不靠 `position: sticky`），休息結束後縮成小橫幅，不直接消失。

## 規劃時的決定（我替你做的）

1. **目前的「紀錄頁」沒有逐組的訓練紀錄**（`Records.tsx` 只有「本週訓練 N 次」）。所以新增一頁「訓練紀錄」`/records/workouts`，列出最近完成的訓練，每個動作的每組重量、次數、休息。從「我的紀錄」的訓練卡片連過去。
2. **提示音用 Web Audio 自己產生**（880 Hz 短嗶三聲），不放音檔。iOS 要求在使用者點擊時先啟用音效，所以在按「完成這組」時呼叫 `unlockRestSound()`。
3. **提示音可以關掉**：計時列加一個 🔔／🔕 按鈕，存在 `localStorage` 的 `gac.restSound`（預設開）。健身房有人不想出聲。
4. **Wake Lock 在整個訓練進行中都開著**，不只在休息時。組間和做組時螢幕都可能自動鎖定，使用者要解鎖才能記錄。頁面切回前景時（`visibilitychange`）重新申請，因為瀏覽器切到背景時會自動釋放。
5. **按「跳過」不再讓計時列消失**，改成直接顯示「已休息 m:ss」的小橫幅。超過 1 小時才隱藏（沿用 `HOUR_MS`）。
6. **固定的計時列用 `position: fixed`**，下面放一個同高度的佔位元素（用 `ResizeObserver` 量高度），避免內容被蓋住。實作前先在瀏覽器手機尺寸重現原本 sticky 失效的原因，記在交接備註。
7. 休息欄的格式沿用 `formatRest`（`1:30`）；沒有紀錄的組（每個訓練的第一組、或舊資料）顯示「—」。
8. iOS 的靜音開關會讓 Web Audio 不出聲。支援 `navigator.audioSession` 時把 `type` 設成 `"transient"`（短暫壓低音樂、不打斷），不支援就算了，靠畫面閃爍。

## Global Constraints

- 使用者看得到的文字一律是繁體中文。
- 震動模式：`[300, 150, 300, 150, 300]`（毫秒）。
- 提示音：三聲 880 Hz 正弦波，每聲 150 ms，間隔 150 ms，音量 0.3。
- 閃爍只在「休息結束」那 3 秒（沿用 `END_NOTICE_MS = 3000`）；`prefers-reduced-motion: reduce` 時不閃，只換底色。
- 每一個瀏覽器 API 都要先檢查存在（`typeof navigator.vibrate === "function"`、`"wakeLock" in navigator`、`window.AudioContext ?? window.webkitAudioContext`），不存在就略過，不能丟錯。
- 訓練紀錄 API：一頁 10 筆，只回傳已結束（`ended_at` 不為 null）的訓練，依 `ended_at` 由新到舊。
- 不要 stage `.claude/` 和 `skills-lock.json`。本機檢查：`npm test`、`npx eslint apps packages`、`npx prettier --check apps packages db docs`。

## Review Focus

1. **按「跳過」之後又完成下一組**：計時要從新的 `lastCompletedAt` 重新倒數，不能卡在「已休息」。
2. **iOS LINE 內建瀏覽器沒有 `navigator.vibrate`、可能沒有 `wakeLock`**：頁面不能壞，提示音和閃爍還是要有。
3. **從背景切回來時休息早就結束**：不能補播一次提示音或補震動（只有在畫面上看著倒數歸零才提醒，沿用 `wasResting`）。
4. **組列表在 375 px 寬時**：五欄加「修改」按鈕不能擠到換行或水平捲動。
5. **計時列高度改變**（按鈕換行、從倒數變成小橫幅）：佔位高度要跟著變，內容不能被蓋住。

## 交接備註

- 原本 sticky 失效的原因沒有重現：controller 用暫時的 harness 頁面在瀏覽器窗格 375 px 檢查的是新程式；舊的 sticky CSS 看起來沒有錯，懷疑是 LINE iOS 內建瀏覽器，因為不確定所以直接改成 `position: fixed`。
- 瀏覽器窗格隱藏時不會繪製畫面，ResizeObserver 不觸發，佔位高度要等畫面繪製才更新；實機不受影響。
- 和計畫不同的地方：
  - Records 訓練卡片改成不是連結、底下兩個連結（避免巢狀 `<a>`）。
  - 提示音按鈕的 aria 改成固定名稱 `提示音` 加 `aria-pressed`。
  - 歷史 API 的 `nextBefore` 用多抓一筆（`limit + 1`）判斷。
  - 組列表多一個固定寬度的操作欄（共 6 欄），表頭才會和數字對齊。
- 重新開啟 LIFF 時，在按下一次「完成這組」之前不會有提示音（震動和閃爍還是有）；實機測試不要當成 bug。
- 本機要先 `npm ci`（`@fastify/rate-limit` 缺）；esbuild 的 install script 沒有核准，目前不影響測試。

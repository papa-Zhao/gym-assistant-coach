# PR 9.1: 問 AI 文字對話 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在聊天室直接打字問 AI（菜單、飲食、訓練建議），api 組好個人上下文後呼叫 Haiku，bot 用「AI 建議」Flex 卡片回覆，頁尾附免責聲明；安全規則寫在系統提示，另由程式檢查。

**Architecture:**

- bot：不是體重指令、也不是「早餐／午餐…」開頭的文字，一律轉給 `POST /internal/ai/ask`。「重新開始」清除對話上下文。Rich Menu「問 AI」改成三個常見問題的 quick reply。
- api：`withAiUse("chat")` 扣次數，接著組上下文（個人檔案與目標、近 7 天訓練、近 7 天飲食達成率、今日剩餘、最近 10 則對話），用 `callStructured` 呼叫 Haiku（`effort: "medium"`）。回答是 structured output（標題、0–3 個選項、內文），對應設計稿的卡片版面。伺服器再做安全檢查，附上提醒。
- 對話存在 `ai_conversations`／`ai_messages`（migration 0010），保存 90 天。log 不記錄對話內容。

**Tech Stack:** 沿用現有套件，不新增。

**Spec:** [docs/specs/2026-10-15-gym-assistant-coach-design.md](../../specs/2026-10-15-gym-assistant-coach-design.md) §5（`ai_conversations`／`ai_messages`）、§6.2（安全下限）、§6.6、§7、§8.4、§10 PR 9。設計稿：`Flex-Advice`（畫布 https://claude.ai/artifact/5Ti3ik18QgMvxf4vtZwbpA）。

## 規劃時的決定（我替你做的）

1. **回答用 structured output，不是純文字。** 規格 §7 寫「一般建議用純文字」，但設計稿的卡片有標題、選項、內文三塊，用 JSON schema 才排得出來；9.2 的課表也可以加在同一個 schema。
2. **卡片頂端的「今天還能吃 … kcal」由伺服器計算**，不交給 AI，數字一定正確。
3. **沒有個人檔案時，熱量安全下限用 1,500 kcal。** 不知道性別時取兩個下限中較高的那一個，比較保守。
4. **AI 回傳格式錯誤（`invalid`）時回「AI 忙碌」，次數照扣。** token 已經花掉了；和餐點流程一致，只有 `AiUnavailable` 才退回次數。
5. **過期對話在每次提問時順便刪除**（全體使用者 90 天前的訊息）。不用另外加排程；PR 10 做資料權利時再評估是否改成排程。
6. **只有成功回答才寫入對話**（問題和回答一起寫）。拒答、忙碌、超過上限都不寫，所以歷史紀錄一定是一問一答成對。
7. **bot 的錯誤對應抽成共用函式**（8.1 的已知問題），文字記餐、照片記餐、問 AI、餐點按鈕共用，原有行為不變。
8. **問題長度上限 500 字**，超過時 bot 直接回提示，不呼叫 api。

## Global Constraints

- 使用者看得到的文字一律是繁體中文。
- 模型 `AI_MODEL`（`claude-haiku-5-5`）。系統提示加 `cache_control`，不設 `temperature`／`top_p`／`top_k`，不用 prefill，處理 `stop_reason: "refusal"`。問 AI 用 `effort: "medium"`；餐點與器材維持 `"low"`。
- 系統提示是固定字串，不放日期或使用者資料；使用者資料放在最後一則 user 訊息。
- log 只記 token、耗時、`stop_reason`、錯誤類別名稱；**不記問題、回答、上下文內容或使用者 ID**。
- 每日上限 `AI_DAILY_LIMITS.chat`（20 次，台北日期，已存在，不需要改 `ai_usage_daily`）。拒答、格式錯誤都算一次；`AiUnavailable` 退回。
- 熱量安全下限：有個人檔案時用 `calcTargets(...).floorKcal`（BMR 與 1,200／1,500 取大）；沒有時用 1,500。
- 免責聲明固定為「AI 建議僅供參考，不能取代醫師或營養師的專業意見。」，每張卡片都有。
- bot 呼叫 api 的逾時：問 AI 30 秒（api 端 Anthropic 用戶端仍是 `AI_CLIENT_TIMEOUT_MS` 20 秒、不重試）。
- 不要 stage `.claude/` 和 `skills-lock.json`。本機 lint 用 `npx eslint apps packages` 和 `npx prettier --check apps packages db .github docs`。

## Review Focus

1. **對話歷史順序與成對**：送給 Claude 的 `messages` 必須 user／assistant 交錯、以 user 開頭、以本次問題結尾；只取目前對話最近 10 則（5 組）。（Task 1、Task 4 測試）
2. **AI 建議每天吃低於下限的熱量**：例如「每天吃 1,000 大卡」，下限 1,500 時卡片要附上提醒；「晚餐約 560 kcal」這種單餐數字不能誤判。（Task 2 測試）
3. **AI 回傳超長或空白的欄位**：標題、選項、內文要截斷；標題空白時用「AI 建議」；選項超過 3 個只留前 3 個。（Task 2 測試）
4. **沒有個人檔案、沒有任何紀錄的新使用者**：上下文要寫「尚未填寫」「沒有記錄」，不能出現 `NaN`、`undefined` 或除以 0；卡片不顯示「今天還能吃」那一行。（Task 3 測試）
5. **使用者封鎖後又解除、或 api 找不到使用者**：api 回 404，bot 回「AI 忙碌」，不顯示「找不到這一餐」。（Task 5 測試）
